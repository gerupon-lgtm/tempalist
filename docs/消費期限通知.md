# 管理リストの消費期限通知

対象: v0.6.0 ／ 2026-09-14

## 使い方

1. 管理リストの項目の「編集」で、任意の消費期限を入力する。1項目につき最大1日付で、空欄は期限なし。年を含めて入力し、既存と同じ数字補完・カレンダーピッカーを使える。
2. 管理リストの「通知を設定」で、そのリストの通知をONにする。初期状態はOFF。初回は端末の通知許可・登録を行う。
3. 「設定」→「消費期限の通知」→「通知時刻を変更」で、全管理リスト共通の時刻を設定する。初期値09:00。前日と当日とも同じ時刻を使う。通常チェックリストの通知時刻は変更しない。

通知対象は、通知ONの管理リストにある「消費期限あり・未消費」の項目だけ。ペットシートなど期限がない項目は対象外。項目名・コメント・管理リスト名は通知APIへ送らず、通知表示も既存の汎用文面を使う。通知を開くと該当管理リストへ移動する。削除済みなら管理一覧に戻る。

## 状態変更

| 操作 | 消費期限 | 通知予約 |
| --- | --- | --- |
| 期限を設定・変更 | 入力した日付を保存 | 未来の前日／当日分を作成・更新 |
| 期限を空にする | クリア | 残る予約を取消 |
| 管理リストで消費済みにチェック | 保持 | 残る予約を取消 |
| 消費チェックを外す | 保持 | 未来の通知を再予約 |
| 対応リストで購入済みにする | クリア | 対象外。前回対応日時は更新 |
| 購入済み操作を「元に戻す」 | 購入前の期限を復元 | 消費済み状態へ戻るので通知しない |
| リストの通知をOFF | 保持 | その管理リストの予約を取消 |
| 項目／管理リストを削除 | データごと削除 | 残る予約を取消。対応リストからも消える |
| 共通通知時刻を変更 | 保持 | 全管理リストの未来の予約を更新 |
| この端末の通知を停止 | 保持 | 通常・管理両方の通知をOFFにして停止 |

過去の通知時刻は遡って送らない。消費期限そのものが過ぎていても編集・保存できる。通知ONで期限未設定のリストにも、後から期限を追加できる。

## 日付と時刻

消費期限は時計上の瞬間ではなく暦日なので、`YYYY-MM-DD`で保存する。APIの`scheduledAt`は端末のIANAタイムゾーン（取得不可時Asia/Tokyo）で時刻を組み合わせ、UTCのISO形式へ変換する。「前日」は単純な24時間減算ではなく前の暦日の共通時刻。夏時間で指定時刻が存在しない日は、その後の最初の有効な分（最大3時間以内、同日）を使用し、重複時刻は早い方を使う。日付自体が消滅した地域など、同日内で有効時刻を求められない通知枠は作成せず、他の項目・通常通知の同期と取消は続行する。端末のタイムゾーン変更後は次回同期で計算し直す。

指定時刻を通知基盤へ予約する。既存基盤の配送・端末の状態によって実際の表示時刻は前後しうる。2026-09-12の基盤調査では最大5分の先読み設定が確認されているため、実機確認は指定時刻の5分前から行う。今回の改修で基盤の先読み設定は変更しない。

## 保存・移行・同期

- 保存形式3: 管理項目の任意`expiryDate`、管理リストの任意`notificationEnabled`、設定の任意`expiryNotificationTime`を追加。旧データの未設定値はそれぞれ期限なし／OFF／09:00として扱う。
- 消費期限入力欄を含む項目保存、通知ON/OFF保存、共通時刻保存で形式3へ移行。旧形式1・2は読み込み可能。旧アプリは形式3を拒否し、データを上書きしない。移行先もv0.6.0以降を使う。
- 全体バックアップに期限を含める。取り込み時は項目・リストIDを再発行し、管理通知はOFF、共通時刻は移行先の設定を保持する。通常テンプレート共有・あとキュー起動URLの形式は変更しない。テンプレートから消費期限はコピーしない。
- 項目IDと通知枠ごとに既存reminderIdを再利用し、管理リストIDを端末内対応表に保持する。通知APIの4フィールド契約は変更しない。端末資格情報は全体バックアップにも含めない。
- 同期は既存Outbox・再試行・端末登録を共用する。オフラインでも期限や消費状態は保存できるが、予約／取消の反映は通信復帰後になる。既に配送された通知は取り消せない。失敗時は「設定」の通知欄から同期を再試行する。

## 確認範囲

単体テストで任意日付・不正値、前日／当日の時刻、夏時間、消費・購入・取り消し、時刻変更時のID維持、削除取消、過去時刻、バックアップと形式移行を検証する。ブラウザでは項目編集から通知登録・時刻変更・通知からの移動・購入と取り消しまで確認する。APIはテスト用応答で検証し、実機への配送はAndroid/iOSでの試用が必要。
