# 連動リスト 初版仕様

作成日: **2026-09-13** ／ 仕様版: **1.0**  
状態: **基本仕様合意済み・未実装**  
既存アプリの確認版: v0.4.4

本書は、このタスクで合意した新機能をまとめた追加仕様です。既存の通常チェックリストを置き換えず、併用できる「連動リスト」を追加します。現行機能は [機能・操作ガイド](機能・操作ガイド.md) を参照してください。実装上の補足案は11章に分け、合意事項と区別します。

## 1. 目的と用語

冷蔵庫の食品、猫の餌、日用品、実験備品などで、不足・消費を記録すると購入や補充の対象が集まり、対応すると元の状態が戻る仕組みを設けます。数量や入出庫を計算する在庫台帳ではなく、要対応かどうかをチェックで管理します。

| 用語 | 意味 |
| --- | --- |
| 連動リスト | 管理リストと共通の対応リストが連動する機能全体 |
| 管理リスト | 「冷蔵庫」「猫の餌」など、継続して使う元のリスト。複数作成可能 |
| 対応リスト | すべての管理リストの要対応項目を自動集約する、共通の1つのリスト |
| 要対応チェック | 管理側のチェック。ONは不足・購入・交換などの対応が必要な状態 |
| 対応完了チェック | 対応側のチェック。購入・補充などが済んだことを示す操作 |
| 前回対応日時 | 直近の対応完了日時。在庫用途では前回購入日に相当 |

チェックの意味を「在庫あり」と取り違えないよう、管理画面に「不足・対応が必要なものにチェック」と案内します。

## 2. 初版の範囲

- 管理リストを複数作成し、項目を管理できる。
- 要対応チェックで共通の対応リストへ自動追加する。
- 対応完了チェックで元の要対応チェックを解除し、前回対応日時を更新する。
- 対応リストには項目名と元の管理リスト名を表示する。
- 同じ管理リスト内では項目名の重複を防止する。
- 通常のテンプレートを管理リスト作成にも共用する。
- 対応完了の誤操作に「元に戻す」を用意する。
- 保存・表示する対応記録は前回分のみ。将来、履歴を蓄積できる構造にする。

管理リストと対応リストは繰り返し利用し、リスト全体の「完了を確定する」は設けません。初版の連動リストには期限・通知を設けず、項目単位の期限も扱いません。

## 3. 画面構成

上部ナビゲーションを **リスト｜管理｜テンプレート｜設定** の4タブとします。既存の「リスト」は通常チェックリストのままです。

### 管理タブの入口

上部に「対応リスト（要対応○件）」を置き、その下に管理リスト一覧と「管理リストを作る」ボタンを置きます。対応すべきものがあるか、購入時にどこを開くかがすぐ分かる構成にします。

### 管理リストの詳細

管理リスト名、各項目の要対応チェック、項目名・コメント、前回対応日時を表示します。未対応の項目は前回対応を「未記録」とします。名前・項目の編集後も連動を維持します。

### 共通の対応リスト

未対応項目を集約して表示し、各行に対応完了チェック、項目名、元の管理リスト名を置きます。元の管理リストへ戻る導線を設けます。対応済み項目は通常の一覧から外れます。初版では対応済み履歴の画面は作りません。

| 表示例: 項目名 | 元の管理リスト |
| --- | --- |
| 洗剤 | 自宅の日用品 |
| 洗剤 | 研究室の消耗品 |
| 猫の餌 | 猫用品 |

対応リストに項目を二重入力する運用は不要です。管理リストでチェックした項目から生成します。

## 4. チェック連動

| 操作 | 管理側の結果 | 対応側の結果 | 前回対応日時 |
| --- | --- | --- | --- |
| 管理項目をON | 要対応になる | 対象を1件表示 | 変更しない |
| 管理項目をOFF | 要対応を取り下げる | 対象を外す | 変更しない |
| 対応側で完了チェック | 元の項目をOFFにする | 対象を外す | 操作時刻に更新 |
| 対応完了を元に戻す | 元の項目をONに戻す | 対象を再表示 | 完了操作直前の値へ戻す |
| 再び管理項目をON | 次の要対応になる | 再び1件表示 | 前回値を保持 |

同じ元項目を重複追加しません。対応完了は対象の元項目にだけ作用し、同名の別項目には影響しません。元のリスト名・項目名が変更されても、固定IDによる紐づけを維持します。

「元に戻す」は今回の対応完了を取り消す機能であり、過去の履歴をさかのぼって編集する機能ではありません。対象や前回対応日時をまとめて戻し、取り消した購入を前回購入として残さないようにします。

## 5. 重複チェック

同一管理リストの項目名は、前後の空白を除いた値で比較します。

- 追加時・名前変更時に同名項目があれば保存せず、「同じ名前の項目があります」と案内する。
- 別の管理リスト間では同名項目を許可する。
- 名前変更時に自分自身を重複として扱わない。
- 通常のテンプレートと通常チェックリストに、この新しい重複制限を一律適用しない。
- 全角・半角、大文字・小文字などの追加の同一視は初版の合意に含めない。前後空白以外の表記は勝手に変更しない。

## 6. テンプレートの共用

テンプレート自体に「通常専用／管理専用」という固定用途を持たせません。同じテンプレートを、作成時の入口に応じて使い分けます。

| 作成の入口 | 作るもの |
| --- | --- |
| 通常の「リストを作る」 | 通常チェックリスト |
| 「管理リストを作る」 | 管理リスト |

名前・項目名・コメント・順番を基に、新しいリストの内容を作ります。チェック状態や前回対応日時はテンプレートへ持たせず、作成した管理リストの項目側で管理します。初回は要対応OFF、前回対応日時なしとします。

テンプレートに同名項目がある場合、管理リスト作成前に修正を案内し、重複したまま作成しません。自動統合・自動削除・黙って名前を変更する処理は行いません。作成後にテンプレートを編集しても、管理リストへ自動反映しません。

「食品」「日用品」「実験備品」は共用テンプレートの用途例です。追加する具体的な初期項目は、この仕様ではまだ確定していません。共通の対応リスト自体にはテンプレートを設けません。

## 7. 前回対応日時と将来の履歴

初版は項目ごとの前回対応日時だけを保存・表示します。利用者の用途では前回分で足りるため、履歴全件の保存、履歴一覧、履歴検索は作りません。

将来の拡張に備えて管理リストと項目に固定IDを持たせ、対応完了時の状態変更と日時更新を1か所の処理にまとめます。将来、その処理から対応履歴を追加できる構造とします。履歴機能を追加する前の過去の購入・対応記録は復元できません。

日時は既存規約どおりUTCで保存し、端末のタイムゾーンで表示します。端末時計による記録であり、署名付き証明ではありません。

## 8. 既存機能との境界

- 通常チェックリストのチェック、完了、期限通知、証跡メールなどは従来どおり扱う。
- あとキューから通常チェックリストを作る既存連携は維持する。管理リストや共通の対応リストへのあとキュー連携は設けない。
- テンプレートは既存の「テンプレート」タブで共用する。
- 完了リストの保持期間による自動削除を、継続利用する管理リストに適用しない。
- 業務データは端末内に保存し、通知共通基盤へ管理項目・チェック内容を送信しない。この機能のための通知API追加は不要。

## 9. 初版で行わないこと

在庫数量・残量・単価・購入金額の計算、項目別期限・通知、複数の独立した対応リスト、対応履歴全件の保存、あとキュー連携、管理リストのクラウド同期は対象外です。対応リストの名称変更や管理項目の他リストへの移動、管理側からテンプレートへの書き戻しは、今回の会話で合意した追加機能には含めません。

## 10. 受入確認

以下は実装後に確認する条件であり、現時点で試験済みという意味ではありません。

1. 「冷蔵庫」「猫用品」など複数の管理リストを作り、それぞれの要対応項目が共通の対応リストへ集まる。
2. 異なる管理リストに同じ項目名を登録でき、対応側では元リスト名で区別できる。
3. 同じ管理リスト内の重複は、項目追加・名前変更・テンプレートからの作成時に防止する。
4. 管理側でON/OFFを繰り返しても重複せず、手動OFFでは前回対応日時を変更しない。
5. 対応完了で正しい元項目だけがOFFになり、前回対応日時を更新する。
6. 「元に戻す」で要対応状態と以前の日時が復元される。
7. 再購入時は前回日時を新しい値へ更新し、履歴全件は作らない。
8. 名前の変更後もIDによる対応関係を保持する。
9. 同じテンプレートから通常リストと管理リストを作り、互いのチェックや編集が独立している。
10. 再読み込み後も管理状態・前回対応日時が残り、通常チェックリストの保持期間で消えない。
11. 4タブをスマートフォン幅で操作でき、共通の対応リストと元リストの間を移動できる。
12. 既存の通常リスト、通知、あとキュー連携、バックアップが損なわれない。

## 11. 実装時の補足案・判断事項

以下は合意事項を成立させるための設計案です。具体的な保存形式や操作表示は実装時に決め、決定後に本書へ反映します。

### 保存と整合性の案

管理項目の「要対応」状態を唯一の保存元とし、共通の対応リストは要対応項目を集めた表示として生成する方式を推奨します。独立したコピーの二重保存を避け、完了操作1回で要対応と前回対応日時をまとめて保存します。保存に失敗した場合は完了した表示にせず、元の状態を維持します。

名前ではなく管理リストID・項目IDで対象を指定します。連打や別タブの更新があっても、古い画面から新しい状態を上書きしない検証を入れます。取り消しも対象の操作後に状態が変わっていない場合だけ適用するなど、後続操作を消さない方式を採ります。

### 詳細設計で決める項目

| 項目 | 検討する内容 |
| --- | --- |
| 「元に戻す」の寿命・表示 | 表示場所、受付時間、画面移動・再読み込みをまたぐか。履歴機能とは別に定義する |
| 対応リストの並び | 元リスト順・項目順、または要対応になった順など。元リスト名は必ず表示する |
| 管理側の並び順ロック | 共用テンプレートの初期値を引き継ぐか、管理側の変更方法 |
| 削除 | 項目／管理リストを削除する確認と、対応側に対象を残さない扱い |
| バックアップと移行 | 管理データ・前回対応日時を保存／復元する形式、旧データの読み込み、新版を旧版へ持ち込んだときの扱い |
| テンプレートの重複修正導線 | 作成を止めた後、どの項目が重複しているか示してテンプレート編集へ戻す |
| 初期サンプル | 食品・日用品・実験備品などの具体的な項目。現行5種との併存 |

保存形式の変更では、旧版との互換を検討し、未知のschemaVersionを推測で取り込まない規約を守ります。既存データを削除して移行する方式にはしません。
