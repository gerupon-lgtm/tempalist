# PWAのインストールと更新（v0.3.1）

## 通常Chromeが旧版のままの場合

1. 元の画面に未保存の入力があれば保存する。
2. 同じ通常Chromeで [更新専用ページ](https://tempalist.sikumilab.com/update/) を開く。
3. 「更新を確認・適用する」を押す。通信が必要。完了したら「アプリへ戻る」を押す。
4. 画面下の版数がv0.3.1以降になっていることを確認する。

この操作はService Workerの更新・適用だけを行う。localStorage、リスト、テンプレート、通知資格情報を削除せず、通知の再登録も要求しない。ブラウザの「サイトデータを削除」は対策手順に含めない。

シークレットタブは通常タブと保存先が別なので、そこで新版が見えても通常タブの更新が完了したことにはならない。

## インストール

- v0.3.0まではiOSの通知設定にホーム画面追加案内があったが、Androidのインストール案内とbeforeinstallpromptの処理は未実装だった。
- v0.3.1はChromeからbeforeinstallpromptを受けたときに、ヘッダ下へインストール案内を表示する。ネイティブのインストール画面は利用者がボタンを押したときだけ開く。「あとで」でその画面の案内を閉じられる。
- 設定の「アプリのインストール・更新」には常に手順を表示する。Android Chromeのメニューから「ホーム画面に追加」または「アプリをインストール」を選ぶ。iOSでは共有メニューから追加する。
- ブラウザがイベントを出さない場合、インストール済みの場合、プライベート閲覧等ではアプリ側からネイティブの案内を強制表示できない。イベントがない場合も手動操作の案内は表示する。
- ホーム画面のアプリで実行中（standalone）の場合、インストールの勧誘を表示しない。アプリをインストールする操作と、通知を許可する操作は別。

## 再現した原因と修正

旧版はアプリ一式をCache Storageから優先して返し、新しいWorkerの自動適用は行わない。新版は待機状態になり、設定画面だけに出る更新ボタンを押すまで古い画面のままになる。

さらに、旧版の `cache.addAll(SHELL)` はHTTPキャッシュを再利用していた。アプリの旧ファイルにmax-age=3600を付けた隔離Chromeで、0.3.0のキャッシュに0.2.1のversion.jsが取り込まれる現象を再現した。実機のキャッシュ内容自体は未取得だが、報告された「通常タブだけ旧版」の原因となる経路をコードと再現環境で確認した。

対策：

- SWインストール時は全リソースを `Request(..., {cache:'reload'})` で取得し、HTTPキャッシュを使い回さない。
- 保存したversion.js・manifestの版がWorkerの版と一致するか検査する。不一致なら新版のインストールを失敗させ、旧版を継続する。
- キャッシュ優先の配信を維持し、版の異なるHTMLとJSを混在させない。無条件のskipWaitingは行わず、利用者の更新操作で適用する。
- 待機中の新版をヘッダ下の全画面共通案内へ表示。設定に常設の「更新を確認する」と更新ページへのリンクを置く。
- 起動・画面復帰・オンライン復帰時も更新を確認する。復帰時は60秒間隔に抑制。通信失敗や15秒タイムアウトは処理し、入力操作を妨げない。
- v0.3.1以降は、未保存の備考・変更中のダイアログがあると適用を止める。他タブが新版を適用してcontrollerchangeが起きた場合も、未保存なら再読み込みを保留する。
- `/update/` は旧版Workerのキャッシュ優先ナビゲーション対象外。更新専用JSは過去のアプリモジュールをimportせず、新版の確認・適用を行う。25秒タイムアウトと再試行案内を持つ。

## 検証

`npm run test:browser` の `scripts/browser-pwa.mjs` は、gitの0.2.1実装（7c86310）と現在の配信ファイルを切り替える一時サーバーを使用する。ブラウザ検証でこの過去コミットを取得できるリポジトリ履歴が必要。利用者のブラウザプロファイルは使用しない。

実Workerで古いHTTPキャッシュからの更新、版の整合、localStorage文字列の維持、更新専用ページからの復旧、次版への案内・適用、備考の未保存防止、更新後のオフライン起動を検証。インストールイベントとユーザー操作は模擬イベントで確認する。実AndroidでのOSインストール画面と利用者の既存プロファイルでの最終確認は別途行う。

参考：[ChromeのService Worker更新](https://developer.chrome.com/docs/workbox/handling-service-worker-updates)、[Service Workerのライフサイクル](https://web.dev/articles/service-worker-lifecycle)、[インストール案内の実装](https://web.dev/articles/customize-install)。

補足検証：利用者のプロファイルとは別の通常Chromeプロファイルでも、インストール条件エラーがないこと、実際のbeforeinstallpromptによる案内表示、設定への画面遷移後の手動案内を確認した。OSのインストール確定操作は行っていない。
