# 画面設計

`!=テンパリスト`（英語表記: NOT EQUAL TEMPALIST）。スマートフォン優先。PCでも主要フローを完結させる。

## v0.1.6の実装状態

S-01〜S-08を実装。ヘッダに専用アイコン・アプリ名・英語表記、共通フッターに小さく `v0.1.6` と `© 2026 SIKUMI LAB` を表示する。2026-09-10の指摘を受け、A1改画像との差を補正した確認版。背景 #fffefe、白いカード、薄いコーラル #fcf3f4 のチェック済み行、アイコン・チェック・主要ボタン共通の #f5614c。英語名の単語間は約1文字分にし、英語名の自然な幅を基準に日本語名の字間を調整する。固定205px幅と英語名の均等割り付けは廃止。

以下の通知トグル・自動ON・ホーム画面追加案内はP4の計画。現在は通知機能が準備中であることを表示し、許可要求やAPI通信を行わない。サンプルは初回保存時に5種を投入する。オフライン起動・Service WorkerもP4で実装する。

S-05は各編集ダイアログの保存ごとに反映し、並べ替えは即保存する。未保存ダイアログを閉じる際は破棄を確認する。容量不足では別の整理ダイアログを重ね、元の入力を保持したままキャンセル・整理・再試行できる。S-08の登録後は作成した下書きの詳細へ進む。

## 0. デザイントークン

**確定方針**：日常・工場・研究室で使いやすい、落ち着いた配色と視認性を優先する。Google Fontsのゴシック系を使用し、読み込めない場合に備えて端末標準フォントも指定する。書体は発案者の指定によりNoto Sans JPで確定。操作感の確認はT-22で継続する。

Google Fontsから400・500・600・700をdisplay=swapで読み込み、以下の順で表示する。

```css
:root {
  --font-sans: "Noto Sans JP", system-ui, -apple-system, "Hiragino Sans", "Yu Gothic", "Meiryo", sans-serif;
  --font-size-base: 16px;      /* iOSで入力時に拡大されない下限 */
  --line-height: 1.7;
  --tap-target-min: 44px;      /* ドラッグハンドルとチェック領域の最小寸法 */
}
```

- **アイコンはインラインSVGを自前で持つ**（単一セット）。基準24px、装飾以外は `aria-label` 必須。**ライブラリを混在させない**
- 画像は扱わない
- Webフォントの取得に失敗しても標準フォントで表示・操作を継続する。オフライン時も同様
- 白に近い背景を優先する指定により、OSのダーク設定でもライト配色を維持する。以前の自動ダーク配色の想定は廃止
- 基本文字 #142432、補助文字 #627283、リンク #d63250、境界 #cfd9e3。コーラル上のボタン文字は画像と同じ白。19px・700の太字とし、大きな文字としてのコントラスト3:1以上を確保する
- CSS変数で配色を管理。独立SVGアイコンのfill、index.htmlのtheme-color、manifestのtheme_colorにも同じアクセントを反映する
- `prefers-reduced-motion: reduce` のとき、確定演出（S-02）を出さない

## 3. 主要画面の項目

### S-02 チェックリスト詳細
- ヘッダ: タイトル、進捗（3/8）、期限、通知トグル
- 項目行: チェックボックス（タップ）／ラベル／メモ／**右端の↑↓ボタン**／編集・削除用の⋯メニュー
- チェックボックスの領域と右端の操作領域を除いたカード全体を約450ms長押しすると、半透明カードが浮き上がり指／ポインターに追従する。元の位置を薄く残し、移動先を線と「ここに移動」で示す
- 長押し成立前に10pxを超えて動いた場合や短いタップでは開始しない。指を離したときだけ保存し、pointercancel・捕捉解除・Escape・画面離脱では保存せず表示を戻す
- **スワイプには何も割り当てない**。項目本文では通常の縦スクロールを維持する
- ドラッグ中は画面上端・下端でその方向へ自動スクロールする。S-05でも同じ操作とし、実使用で問題があれば調整する
- ドラッグが使えない環境向けに右端に常時表示の↑↓ボタンを用意する。⋯メニューは編集・削除のみとする
- フッタ: 確定ボタン。未チェックが残る場合は残数を出した確認を挟む
- 確定後: 全編集操作を不可にし、`settledAt` を「2026/09/09 08:12 確定」の形式で表示。再オープンボタンを出す

### S-03 生成ダイアログ
- テンプレート選択（`active` のみ）、タイトル（必須）、期限（日付＋時刻、時刻は任意）
- 「空から作る」を選べる。タイトルを入力して項目0件で作成し、S-02で項目を追加する
- 期限を入力すると通知が自動ONになる。ブラウザの許可を拒否されたらトグルをOFFに戻す
- 日付は8桁入力で `yyyy/MM/dd`、時刻は4桁入力で `HH:mm` に補完。ピッカーと併用

### S-07 設定
- 完了リストの保持期間（30日／90日／1年／削除しない。初期設定は90日、確定日時から起算）
- エクスポート（JSONダウンロード）／インポート（ファイル選択）
- バックアップのリスト・テンプレートは既存データを残して追加する。同じファイルの再取り込みでも別データが追加される旨を表示。「設定はこの端末のものを維持します。取り込んだデータにも、この端末の保持期間が適用されます」と案内する
- テンプレート1件の共有JSONを選んだ場合はS-08へ進み、内容確認後に下書きで登録する
- アプリ版数の表示
- 通知の再設定・端末登録の解除

### S-04 共有時のURL長超過
- 「共有リンクが長すぎるため作成できません。テンプレートをJSONファイルで共有できます」と表示し、その1件のJSONダウンロードを提示する

### S-06 下書きへの書き戻し
- 上書き先が下書きの場合は「下書きのまま更新」と分かるように表示する。有効化はS-04／S-05で利用者が行う

### 容量不足時の共通案内
- 新規保存できない場合は「保存容量が不足しています。次のリストを作成するには、保存済みデータを削除して空き容量を確保してください」と画面表示し、エクスポート・整理へ案内する
- 「削除しない」では手動削除の案内のみ。他の設定で保持期間内の完了リストも削除する場合は「保持期間内の完了リストを古い順にN件削除します」と対象件数を表示して確認する
- 確認をキャンセルした場合は削除せず、未保存の入力を画面に残して整理後に再試行できるようにする

### S-09 初回サンプル
- [sample-templates.md](sample-templates.md) の5種を初回起動時に投入する。利用者が項目・メモを編集できる

## 4. 通知からの遷移

Service Worker は `routeKey = "list"` を `/list` に解決し、`?reminder=<reminderId>` を付けて開く。アプリ側は端末内の `ReminderMapping` から `checklistId` を引いて S-02 を開く。**対応が見つからない場合は S-01 を開く**（サーバーに問い合わせない）。

## v0.1.2の確認待ち事項

配色は生成画像の色を直接確認して補正した。カード全体の長押しと右端↑↓の組み合わせは発案者の試用確認待ち。Chromeのタッチ入力では通常スクロールとの切り替えを確認済みで、iOS／Android実機での確認は未実施。最終決定後に要件定義書・タスク表へまとめて反映する。

文字の太さについての追加指摘を受け、Noto Sans JPに切り替え。本文・補助文は500、項目本文は16px・500、見出しと主要ボタンは700とした。主要ボタンは白文字。書体・太さも実画面の確認対象とする。

## v0.1.3のカードメニュー・長いメモ（確認版）

- ⋯メニューは外側のクリック／タップ・Escapeで閉じる。同時に開くメニューは1つ。メニューを隣のカードの操作に重ねず、対象カードの中で右側に表示する。
- 短いメモは引き続きカード内に表示する。実際の描画で3行を超えた場合だけ「続きを読む」を付け、カード本文・余白のシングルタップで画面下部に全文を表示する。画面幅・書体読み込みによる折り返しの変化も再判定する。
- 全文表示は時間で消さず、閉じる・外側クリック・Escape・画面遷移で閉じる。長文はスクロール可能。チェックや右端の操作では開かない。長押し・ドラッグ終了後のクリックでは開かない。キーボードは本文へTabで移動してEnter／Space、Escapeで閉じる。
- 書体を変更した目的は画像の文字の太さに近づけるためで、比較用としての変更ではなかった。再確認用に、現在の配色・太さ・データを揃えたZen Kaku Gothic NewとNoto Sans JPの実画面比較を `artifacts/font-comparison.html` と `.png` に出力する。アプリの現在の書体はNoto Sans JPのまま。

2026-09-10：書体はNoto Sans JPで確定。英語ヘッダの単語間を約1文字分へ縮め、その実幅に日本語ヘッダを揃えた（v0.1.4）。

リスト一覧とテンプレート一覧の作成ボタンは、同じ位置・幅156pxに揃える。モバイルでは両画面とも見出しの下に配置し、見出し領域の高さを共通に確保する。PCでは両画面とも右上に配置する（v0.1.5）。

## v0.1.6 — 並び順ロック・タブ復帰・余白

- テンプレート詳細に「作成するリストの並び順ロック」スイッチ、新規作成フォームに同設定を追加。テンプレート自体の編集・並べ替えを制限する設定ではない。
- チェックリスト詳細に「並び順ロック」スイッチを表示。ONではカードの長押しを無効にし、↑↓を非表示にする。チェックと通常の編集は継続できる。確定済みの場合はスイッチも無効にし、再開の案内を表示する。
- 上部のテンプレート／設定タブからリストタブへ戻る際は、直前のチェックリストを表示する。対象の記録は同じブラウザタブの再読込でも維持する。削除済みなら一覧に戻す。「一覧に戻る」やアプリ名のホームリンクを押した場合は一覧を優先する。
- モバイル一覧の固定100px見出し領域を廃止。見出しを画面幅に応じた16〜20pxで1行に収め、段落との間隔6px、作成ボタンとの間隔8pxに詰めた。リスト一覧とテンプレート一覧の作成ボタン位置・幅は引き続き一致する。

並び順ロック直前の期限欄／テンプレート操作欄は下余白8px、ロック欄の上余白は6pxとし、間隔を詰める。

## v0.3.2 詳細タイトルと編集ボタン

チェックリスト・テンプレート詳細の見出しを専用のグリッドに変更。タイトルと編集ボタンを1段目、説明文を横幅全体の2段目に配置し、説明文の長さによって編集ボタンが縮まないようにする。

タイトルは画面幅に応じて17〜22px、字間0、行高1.5とする。「PCセキュリティソフト設定」は320／360／375／393／412／680／1280pxで1行表示を確認。Google Fonts取得時と標準フォントへのフォールバック時を確認した。長文を省略せず、対応ブラウザではauto-phraseで日本語の自然な区切りを優先し、非対応時も通常改行とoverflow-wrapで横はみ出しを防ぐ。

編集ボタンは高さ44px・最小幅60px・改行なし。タイトルが複数行でも高さを変えない。完了リストのタイトルにも同じ文字サイズを適用する。一覧の作成ボタンの配置は既存のまま。

### 期限の日付・時刻入力

日付と時刻の入力欄内の右端にカレンダー／時計アイコンを配置し、端末標準のピッカーを開く。現在の入力をピッカーへ引き継ぎ、選択結果を同じ欄へ反映する。showPicker非対応時は標準入力を表示して選択できるようにする。

入力欄はフォーカス・タップ時に全選択する。数字入力中に日付は年4桁・月2桁の直後に `/`、時刻は2桁の直後に `:` を補う。例えば `2026` → `2026/` → `2026/09/` → `2026/09/10`、`14` → `14:` → `14:30`。数字の貼り付けにも対応し、Backspaceで消した末尾の区切りは再挿入しない。無効な値を勝手に切り捨てず、保存時の既存検証で修正を促す。

期限の保存形式・タイムゾーン・時刻省略時09:00の扱いは維持する。320pxでは入力欄を縦に並べ、375px以上では日付を広めにして横に並べる。

### チェック項目の文字サイズ

項目名は日本語・半角文字の幅を考慮した文字数の目安と、チェックボックス・右端操作を除いた実際の表示幅に応じて調整する。標準16px、下限14px、字間は0〜-0.02em。短い項目や横幅の広い画面では標準サイズを保ち、長文は省略せず自然な区切りで折り返す。テンプレート・完了済みリストにも適用。container query非対応時は16pxの通常改行へフォールバックする。メモの文字サイズとチェック操作領域は維持する。

### v0.3.3 チェック済み項目の取り消し線

チェック済みの項目名に1pxの取り消し線を表示する。チェックを外すと解除する。メモには線を付けない。再読み込み・完了確定後も保存されたチェック状態に従って表示する。

### v0.3.4 Androidの記録共有

「メールアプリへ共有（データ付き）」は、JSONの内容を `.json.txt` のテキスト添付として端末の標準共有へ渡す。形式・再利用方法をボタン下に表示する。ファイル共有非対応時は「本文を共有（添付なし）」を提供し、共有API自体がなければ保存・コピー・メールリンクを使う。「設定 → JSONを取り込む」は `.json.txt` にも対応する。詳細はchecklist-records.md。

### v0.3.5 通知条件の確認と修正

「通知を設定」に期限の日付・時刻欄を追加し、同じ画面で期限・通知ON/OFF・タイミングを保存する。24時間前／1時間前の各欄に具体的な通知日時と、すでに時刻を過ぎているかを表示。期限未設定・未選択・全通知時刻経過を分けて案内する。保存時に再検証し、別画面での期限・通知設定の変更を上書きしない。

### v0.3.6 iOSの標準ピッカー操作

iPhone/iPadではカレンダー・時計アイコンの44px領域をネイティブdate/time入力の直接タップ領域とする。showPickerの呼出しに依存せず、フォーカスでOSのピッカーを開く。キーボード・支援技術も同じ入力を操作でき、背後の装飾ボタンはフォーカス対象から外す。Android・PCの既存のピッカー呼出しと手入力時の全選択・自動区切りは維持する。

### v0.3.7 通知の登録状態

端末登録が保存されていれば「この端末は登録済みです」と同期メッセージを併記し、登録操作のボタンを「この端末の通知設定を確認」にする。停止処理中はその状態を表示する。ブラウザの購読状態を取得できない場合は、登録済み情報を保持したまま確認失敗と同期再試行を案内する。登録済み表示だけで配信成功を意味しない。
