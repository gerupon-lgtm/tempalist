# !=テンパリスト 機能・操作ガイド

対象バージョン: **v0.4.4** ／ 更新日: **2026-09-13**

英語表記: **NOT EQUAL TEMPALIST**  
公開先: [tempalist.sikumilab.com](https://tempalist.sikumilab.com/)

この資料は、現在実装されている機能、使い方、確認済みの動作と残る制約をまとめた入口です。v0.4.4のコード、個別仕様書、2026-09-12までの利用者の実機報告を照合しています。過去の設計案・変更履歴にある「予定」「未実装」は、その時点の記録です。現行機能の確認には本資料を使用してください。

## 1. アプリの目的と保存先

繰り返し使う段取りを「テンプレート」として保存し、実施するたびに独立した「チェックリスト」を作ります。日常の準備、納品確認、工場の始業前点検、実験前の確認などに使えます。

- テンプレートはひな型、チェックリストはその回の実施記録です。テンプレートの変更は作成済みリストへ自動反映しません。
- リスト・テンプレート・備考・チェック結果は、使用している端末のブラウザ内に保存します。アカウントによるクラウド同期や端末間の自動共有はありません。
- 通知基盤には予約・端末購読など通知に必要な情報を送ります。タイトル、チェック項目、コメント、備考は送りません。
- メール共有・ファイル保存・共有リンクでは、利用者の操作により内容を持ち出せます。
- 初回のオンライン起動とアプリの保存が済めば、オフラインでも保存済みデータの閲覧・編集ができます。通知の登録・予約・取消や更新には通信が必要です。

## 2. 画面と基本操作

上部に「リスト」「テンプレート」「設定」のタブがあります。チェックリストを開いたまま別タブへ移っても、「リスト」タブから元のリストに戻れます。「一覧に戻る」を選んだ場合や対象リストが削除された場合は一覧になります。

ヘッダにはアイコンと日本語・英語のアプリ名、下部にはバージョンとコピーライトを表示します。白に近い背景とコーラル系のアクセント、Noto Sans JPと端末標準のゴシック系フォールバックを使用しています。タイトルや項目名は文字数・表示幅に応じて文字サイズなどを調整し、必要な場合は折り返します。詳細画面の編集ボタンは文字数によって縦に伸びない作りです。

### チェックリストを作る

1. 「リストを作る」から、使用中のテンプレートまたは空のリストを選びます。テンプレート詳細の「この型でリストを作る」からも作成できます。
2. タイトルと、必要に応じて期限の日付・時刻を設定します。
3. 作成後に項目を追加・編集できます。新しいリストは未チェック、通知OFFで始まります。

一覧は「進行中」「完了」に分かれます。進行中は期限順（期限なしは後方）、完了は完了確定日時の新しい順です。チェック数と進捗を表示します。

### 項目をチェック・編集する

- チェックボックスでON/OFFを切り替えます。ONで項目名に取り消し線を付け、OFFで解除します。操作は保存されます。
- 各項目には項目名とコメントを保存できます。「⋯」から編集・削除を行い、メニュー外を押すとメニューを閉じます。
- コメントはカードに表示します。長文は最大3行に省略し、続きを表示する操作で画面下部のパネルから全文を確認できます。
- チェックした日時も保存します。チェックを外すと日時を消し、再チェックした時点の新しい日時を記録します。

### 並び替えと並び順ロック

カードのチェックボックスと右端の操作部分を除く範囲を約0.45秒長押しすると、半透明のカードを上下へ移動できます。右端の↑↓ボタンでも1段ずつ移動できます。

「並び順ロック」をONにすると、ドラッグ・↑↓の並び替えを止めます。進行中リストのチェックや項目編集は引き続き可能です。テンプレートでは、新しく作るリストの初期ロック状態を設定できます。作成後のリストでは独立して切り替えられます。テンプレート自体の項目順を固定する設定ではありません。

## 3. リスト全体の備考・完了・再開

項目の下に「リスト全体の備考」を常時表示し、完了前後とも直接入力できます。「備考を保存」で保存します。完了確定やメール・記録の書き出しでも、未保存の備考を先に保存します。

- アプリ内のタブ移動や再描画では入力途中の備考を保持します。ページ終了・再読み込み前には保存してください。
- 編集ダイアログに未保存の変更がある場合は、閉じる前に破棄を確認します。別タブとの競合時には上書きを防ぎ、入力を残して案内します。
- 「完了を確定する」で完了日時を記録します。未チェック項目が残る場合は確認を挟んで確定できます。全項目にチェックしただけでは完了確定にはなりません。
- 確定後はチェック・項目編集・並び替え・期限変更を止めます。備考の編集、記録出力、書き戻し、削除はできます。
- 完了確定で通知をOFFにし、未送信予約の取消を同期します。
- 「再開する」で進行中に戻します。チェック状態と各チェック日時は保持し、完了日時は消します。次の確定時に新しい完了日時を記録します。通知は自動でONに戻りません。
- 完了後に備考を変更しても、完了日時と項目のチェック日時は変えません。

## 4. テンプレート

名前・項目名・項目コメント・項目順・新規リストの並び順ロック初期値を管理します。作成、編集、複製、削除と、「使用中」「下書き」「アーカイブ」の状態変更ができます。リスト作成の選択肢には使用中のテンプレートを表示します。

初期サンプルは以下の5種類です。必要に応じて現場の手順に合わせて編集します。

| テンプレート | 項目数 |
| --- | ---: |
| おでかけ | 7 |
| 納品前 | 7 |
| 顧客訪問 | 7 |
| 工場の始業前点検 | 8 |
| 研究室の実験前チェック | 8 |

### 実施結果をテンプレートへ書き戻す

リストの「テンプレートに書き戻す」から、元テンプレートの上書き、または新しいテンプレートとしての登録を選びます。

- 項目名・コメント・項目順を保存します。チェック状態・チェック日時・期限・全体備考・完了日時は書き戻しません。
- 元への上書きではテンプレート名とロック初期値を維持します。元が下書きなら下書きを維持、アーカイブなら使用中へ戻します。
- 新規登録では名前を指定でき、リストの並び順ロックを初期値として引き継ぎます。
- 元テンプレートが存在しない場合も、新規登録できます。

標準テンプレートをファイルアップロードで一括差し替えする管理機能は保留中です。通常の共有テンプレート取り込みは利用できます。

## 5. 日付・時刻の入力

手入力欄と、欄内のカレンダー・時計アイコンから入力できます。

- フォーカスから50ms後に全選択します。すでに入力中の欄を再タップした場合は全選択を強制せず、カーソル移動ができます。
- 日付は4桁の年、2桁の月を入力した段階で「/」、時刻は2桁の時を入力した段階で「:」を補います。例: `20260913` → `2026/09/13`、`1230` → `12:30`。
- 別欄へ移動した場合や入力・IME変換を開始した場合、ダイアログを閉じた場合は選択予約を解除します。50ms以内に入力を始めたときは全置換を保証しません。
- 時刻省略時はその日付の09:00として扱います。存在しない日付・不正な時刻は保存時に検証します。
- 表示・入力は端末のタイムゾーンに従い、内部の日時はUTCで保存します。

v0.4.4の遅延選択はあとキューの方式に合わせたAndroid編集メニュー対策です。長押しによるコピー操作を禁止するものではありません。メニューが出なくなるかは利用端末での確認が残っています。iOS向けのピッカー直接タップ経路も実装済みですが、自動検証と実機のネイティブ画面の確認は区別しています。

## 6. 期限の通知

### 設定する

1. 設定の「この端末で通知を使う」で端末を登録し、通知を許可します。各リストの通知設定時にも必要な登録処理を行います。
2. リストの「通知を設定」で通知ON、期限、希望するタイミングを選びます。
3. 保存後の結果と、設定画面の通知欄で同期状態を確認します。

| タイミング | 予約する日時 |
| --- | --- |
| 24時間前 | 期限の24時間前 |
| 1時間前 | 期限の1時間前 |
| 期限ちょうど | 期限と同じ日時 |

選んだタイミングで最大3回です。新規リストでは3枠が初期選択されていますが、通知をONにするまで予約しません。既存リストの選択は更新時に勝手に変更しないため、必要な枠は個別に追加します。

未来の通知時刻が1件以上必要です。すでに過ぎた枠は予約せず、すべて過去ならONにできません。あとキューから受信したリストも、期限を設定し通知ONで保存すると予約を同期します。

### 通知と同期の動き

- 予約が同期済みなら、アプリの画面を閉じていてもPush通知を受け取る設計です。アプリを開き続ける必要はありません。
- 通知には固定文を表示し、リスト名・項目・コメントは表示しません。タップすると端末内の対応リストへ進み、対象が見つからない場合は一覧を開きます。
- 期限や選択枠の変更時は予約を更新します。通知OFF、完了確定、リスト削除では不要な予約を取り消します。
- 通信できないときは予約・取消を保留します。未同期のまま閉じた場合、その変更が基盤へ反映されたとは扱えません。取消が届く前には古い通知が来る場合があります。
- 保存後の同期確認は画面上で最大10秒待ち、時間がかかる場合や未同期なら案内します。通知の失敗でリストの保存を取り消しません。
- 設定の「通知の同期を再試行」で再送し、「この端末の通知を停止」で端末の通知利用を停止できます。
- 通常のアプリ更新では再登録不要です。実際に権限・購読・端末資格情報が失われた場合は再設定が必要です。

**送信時刻について:** 2026-09-12の基盤担当の調査では、共通基盤は最大5分先の予約まで前倒し送信する設定でした。そのため「期限ちょうど」でも数分早く届くことがあります。アプリの予約日時自体は期限と一致しています。期限前の送信をなくす変更は基盤側の対応事項で、このアプリでは未対応です。この設定情報は同日の調査結果であり、その後の基盤変更を常時監視しているわけではありません。

### 診断と実機での確認結果

| 項目 | 2026-09-12までの確認 |
| --- | --- |
| Androidの表示テスト | 利用者が表示を確認済み |
| Androidの予約通知 | v0.4.3で基盤からのPush受信と通知表示を確認済み |
| 過去の未着原因・継続配送 | 未確定。1回の成功で解消・継続性を断定しない |
| iOSの通知 | 登録互換性の修正済み。実機での継続配送は未確認 |

Androidの成功例は、日本時間9月12日16:10期限に対し、16:01:54に予約受付、16:06:07にPush受信と表示要求成功を記録しました。利用者からも「通知きました」と報告されています。前倒し設定と整合する結果です。この記録だけでは、その瞬間のアプリの前面・背景状態までは確定しません。

設定の「通知の診断情報」で予約時刻・未同期件数・API操作履歴・Push受信／表示履歴を確認し、コピーできます。「接続を確認する」は接続確認、「通知の表示テスト」は端末内の表示確認であり、どちらも予約通知の実配送を証明するものではありません。API受付、Push受信、表示要求成功、実際に見えた通知を区別して調査します。診断には業務内容や端末の秘密情報を含めません。

## 7. 証跡メール・JSON・PCでの再利用

リストの「メール・記録を書き出す」から、進行中でも完了後でも出力できます。

| 出力項目 | 内容 |
| --- | --- |
| 件名 | チェックリスト名 |
| 本文 | 状態、期限・完了などの日時、全体備考、項目順、項目名、チェック状態、項目ごとのチェック日時、コメント |
| 添付・保存データ | そのリスト1件のJSON。チェック日時、完了日時、備考などを保持 |

「メールアプリへ共有（データ付き）」から端末の共有先を選びます。共有添付はJSON内容の `.json.txt` です。通常の「JSONを保存」とEML内の添付は `.json` です。アプリには `.json.txt` のまま取り込めます。PCのツールが必要とする場合は末尾の `.txt` を外します。

共有できない場合はJSONを保存し、件名・本文をコピーしてメールに添付します。「メールを開く」は添付を自動で付けません。PC向けには本文とJSON添付を含む `.eml` の保存もできます。送信先の指定と実送信はメールアプリで行います。共有先ごとの件名・本文・添付の受け取り方と、実際の送信結果は利用するアプリで確認してください。

### 記録の意味

- 日時は端末の時計に基づく実施記録です。本人認証・電子署名・第三者タイムスタンプ・改ざん検知はありません。
- チェック日時は現在のチェック状態に対応する1件で、過去のON/OFF履歴すべてを保存する機能ではありません。
- 更新前からチェック済みで日時がない項目は「日時未記録」とし、推測で補いません。
- 本文は端末のタイムゾーンとUTCを併記し、JSONはUTCで記録します。出力は書き出し画面を開いた時点の内容です。変更後は開き直してください。
- PCのJSON対応ツールで利用できます。過去に保存したファイルは、アプリでの備考変更・再開・データ削除後も独立して残ります。

## 8. 共有・バックアップ・取り込み

| 方法 | 用途と結果 |
| --- | --- |
| テンプレートの共有リンク | テンプレート詳細の「共有」からリンクをコピー。受取側は確認して下書きに追加 |
| テンプレートの共有JSON | リンクに収まらない場合などにファイルで渡す |
| 設定の「JSONを書き出す」 | テンプレートとチェックリストなどの業務データを全体バックアップ |
| 設定の「JSONを取り込む」 | バックアップ・共有テンプレート・リスト記録を確認して追加 |

テンプレートのリンクには名前・項目・コメント・ロック初期値を含めます。URL全体で8000文字を超える場合は共有JSONを使います。実行リストのチェック状態・備考・完了日時を含む記録のURL共有は未実装です。

取り込みは既存データへの追加で、同じファイルを再度取り込むと別データとして増えます。通知はOFF、設定と保持期間は移行先を維持します。保持期間を過ぎた完了リストは取り込み後の整理対象にもなるため、移行先の設定を確認します。端末の通知資格情報や購読情報はバックアップ・証跡へ含めません。

## 9. あとキューからチェックリストを作る

あとキューで選んだ複数の予定を、項目名・コメント・順番とともに起動URLで受け取り、1つのチェックリストにまとめます。受信画面で内容を確認し、タイトルを必要に応じて変更して「作成する」を押します。開くだけでは保存しません。

- 受信リストは未チェック・期限なし・通知OFFです。必要な期限と通知をテンパリスト側で設定します。
- 同じ連携IDで作成済みなら既存のリストを開き、上書き・重複作成を防ぎます。元の予定IDを記録データに保持します。
- 一方向連携です。テンパリストでのチェックや完了をあとキューへ戻す機能はありません。
- 起動URLは全体8000文字まで。超える場合は項目を分けて送ります。

**実機結果:** Androidでは利用者が連携成功を確認しています。iOSのホーム画面のあとキューからは、その経路で開いたテンパリストに保存され、普段のホーム画面・ブラウザのテンパリストには現れないとの報告です。iOSのブラウザ同士では保存後も残っています。

iOSで普段のホーム画面アプリへ合流する条件は満たしていません。Androidを優先し、iOSは起動経路による保存先の違いがある状態として扱います。iOSの受信を禁止するコードや、保存領域を統合する機能は実装していません。

## 10. 保持期間と容量整理

完了リストの保持期間は、30日・90日・1年（365日）・削除しないから選びます。既定は90日で、完了確定日時から数えます。期間を過ぎた完了リストは起動時などの整理処理で削除します。進行中リストとテンプレートは自動削除しません。

容量不足時は完了リストの削除対象を選んで整理します。書き出すだけでは空き容量は増えず、次のリスト作成に必要な空きを確保するには端末内データの削除が必要な場合があります。「削除しない」では自動削除せず、利用者が選んで整理します。件数の固定上限は設けず、ブラウザの保存可能容量に制約されます。

ブラウザのサイトデータを消すとリストも失われます。重要な記録は、削除・端末移行の前にファイルとして保存します。

## 11. インストールと更新

AndroidはChromeのメニュー、iOSは共有メニューからホーム画面に追加します。対応ブラウザからインストール可能イベントを受けた場合はアプリ内にも案内を表示し、設定には手動手順を常設しています。案内が自動表示されないことだけではインストール不可とは判断しません。

新版を検出すると更新案内を表示します。設定の「更新を確認する」からも確認できます。保存済みのリスト・テンプレート・端末登録は更新で消しません。入力途中の内容を保存してから適用します。

通常の画面が古いままなら、同じブラウザの[更新専用ページ](https://tempalist.sikumilab.com/update/)で「更新を確認・適用する」を押し、アプリへ戻って版数を確認します。シークレットタブで新版が見えても、通常タブの更新完了を意味しません。更新目的でサイトデータを削除する必要はありません。
